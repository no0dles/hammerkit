Compile a TypeScript project with tsc. The task runs in a `node` container, keeps the compiler output as its result, and is skipped when the sources and `tsconfig.json` are unchanged.

## Install first

The task runs the tool from `node_modules`, and a container task only sees the files it
declares and the outputs of its dependencies, so the install must be a dependency. Include
the entry of your package manager ([npm](/docs/catalog/npm), [yarn](/docs/catalog/yarn) or
[pnpm](/docs/catalog/pnpm)) and `extend` the task to add it, which works with any of them
and keeps the entry free of a package manager:

```yaml title=".hammerkit.yaml"
includes:
  npm:
    git: https://github.com/no0dles/hammerkit.git
    ref: v1.22.0
    path: catalog/npm
  tsc:
    git: https://github.com/no0dles/hammerkit.git
    ref: v1.22.0
    path: catalog/tsc

tasks:
  build:
    extend: tsc:build
    deps: [npm:install]
```

`extend` keeps the entry's image, sources and commands and adds the dependency
(see [extending](/docs/task/extending)).

## Tasks

| Task | What it does | Reads | Produces |
|---|---|---|---|
| `build` | Compile the project with tsc. | `package.json`, `tsconfig.json`, `SOURCE_DIR` | `OUTPUT_DIR` |

## Inputs

| Input | Default | Meaning |
|---|---|---|
| `NODE_VERSION` | `24` | Tag of the `node` image the task runs in, e.g. `22` or `24`. The image is `node:<NODE_VERSION>-alpine`. |
| `SOURCE_DIR` | `src` | Folder with the TypeScript sources, relative to the working directory. |
| `OUTPUT_DIR` | `dist` | Folder tsc writes to. It must be the `outDir` of your `tsconfig.json`. |

## Another layout

The entry reads `tsconfig.json` and the `SOURCE_DIR` folder. A monorepo that shares a base
configuration adds it to the task's `src` when it extends, for example
`src: [../../tsconfig.base.json]`.
